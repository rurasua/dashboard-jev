AgenThinkOs — Dashboard de Clasificación de Manifestaciones Geológicas Guía visual para nuevos usuarios

Una sola página web que combina las reglas duras de tu detector actual con un modelo calibrado que entiende formación, composición del gas y tendencia. Funciona con doble click para una lectura, o arrastrando una Boleta completa para clasificar cientos de eventos en minutos.

2. Modo manual — flujo de uso

Para 1 a 3 lecturas interesantes del turno. Una clasificación toma ~1.5 segundos y muestra el veredicto inmediatamente.

  1. Pegar la API key (solo la primera vez)
    Arriba del todo hay un campo API key del proveedor. Pegala, presioná Guardar. Queda en el localStorage de tu navegador — no se sube a ningún servidor. Si el status se pone verde ✓ key cargada, está listo.
  2. Editar la lectura (o usar los valores pre-llenados)
    La columna izquierda tiene los 12 campos numéricos: md, rop, wob, rpm, den_in, den_out, gas_total, c1..c5. Los selects Formación y Operación vienen con valores por defecto del PRD (Kimmeridge + perforando rotando).
  3. Click en "Clasificar con AgenThinkOs"
    ~1-2 segundos mientras el modelo responde. El botón muestra un spinner mientras tanto.
  4. Interpretar los 3 paneles de resultado
    Severidad (badge grande arriba), distribución (qué tan seguro está el modelo de cada una), juicios (probabilidades de gas termogénico y tendencia agravante), y el comparativo con las reglas duras. Si coincide con las reglas, banner verde; si difieren, ámbar o rojo.
  5. La clasificación se guarda en el historial
    Abajo a la derecha, panel Historial. Cada fila tiene botón Recargar que rellena el formulario con esa lectura, para que puedas iterar rápido.
Consejo: si tu navegador pide permisos al cargar la página, deciles que sí. El dashboard necesita hacer fetch al endpoint del modelo.

3. Modo batch — flujo de uso

Cuando tienes un día entero de operaciones (cientos de lecturas). Arrastras los archivos y el sistema detecta solo las críticas.

Qué archivos acepta

ArchivoQué contiene
Boleta DiariaParámetros de perforación (XLS legacy, hoja PARAMETROS)
CromatografíaComposición de gas C1..nC5 por profundidad (XLSX)

La cromatografía es opcional pero altamente recomendada — sin ella no se aplica la regla de gas, que es la que más dispara en casos reales.

Qué hace el sistema

  1. Parsea los archivos en el navegador
    SheetJS lee XLS/XLSX. Tu data nunca sale de tu máquina hasta el momento de clasificar.
  2. Aplica las 3 reglas duras
    gas (factor + absoluto), densidad (caída), ROP (caída). Para Boletas típicas resulta en ~1% de lecturas críticas.
  3. Clasifica solo las críticas con el modelo
    ~1.5s por hit, con barra de progreso y retry automático en caso de rate-limit (429).

Costos y tiempos esperados

Para una Boleta típica (~800 lecturas, ~10 hits detectados):

10 lecturas manuales
~15 s
50 hits batch
~1.5 min
200 hits batch
~5 min
1000 hits batch (auditoría)
~25 min
Costo estimado: ~1000 tokens de input + 50 de output por clasificación → a tarifas estándar de API equivale a centavos de dólar por día de cabina.

4. Glosario rápido

Reglas duras
Las 3 reglas de umbral que ya tienes en anomaly_detector.py (gas factor 5×, densidad caída 5%, ROP caída 80%). Opacas, rápidas, sin contexto geológico.
Modelo calibrado
El modelo de IA que recibe los mismos números MÁS el contexto (formación, operación, composición del gas, historia reciente) y devuelve una severidad con probabilidades. Tarda ~1.5s.
Severidad
Etiqueta categórica: critica, alta, media, baja. La peor de las dos (reglas vs modelo) es la que reporta el sistema.
Termogénico
Gas cuya composición indica origen térmico profundo (presencia de C2, C3, iC4, nC5). El modelo estima la probabilidad en 0-100%.
Tendencia agravante
Si en los últimos 15 minutos la situación empeora (gas subiendo + ROP cayendo + densidad bajando) vs estabilizándose. Probabilidad 0-100%.
CORS
Política del navegador que bloquea requests cross-origin. Por eso el dashboard no se abre con doble-click directo del HTML — necesita el proxy local en http://localhost:8000.
md, rop, wob
md = measured depth (profundidad). rop = rate of penetration (velocidad de perforación). wob = weight on bit (peso sobre la barrena).
Boleta Diaria
Reporte diario de operaciones de perforación. Formato XLS legacy de OAE. Hoja PARAMETROS contiene las lecturas por metro.

5. Setup local — 4 pasos en PowerShell

Si arrancás de cero en una máquina nueva, este es el orden. Tiempo total: ~15 minutos.

Paso 1 — Activar el venv de Python

& 'C:\Users\Geo Estratos\.venvs\typesafe\Scripts\Activate.ps1'

El prompt ahora empieza con (typesafe). Si falla por "execution of scripts is disabled", ejecutá antes: Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Paso 2 — Inyectar la API key en la sesión

$env:TYPESAFE_API_KEY = [Environment]::GetEnvironmentVariable('TYPESAFE_API_KEY', 'User')

Paso 3 — Arrancar el proxy local

python 'C:\projects\Cabinas Geologicas\typesafe-lab\proxy_dashboard.py'

Dejá esta ventana abierta. Verás un mensaje como Abre el dashboard en: http://localhost:8000.

Paso 4 — Abrir Chrome en localhost:8000

NO abras el HTML con doble click (vuelve a CORS). Usá siempre la URL http://localhost:8000.

¿Por qué el proxy? El navegador bloquea requests cross-origin desde file:// (cuando abrís un HTML local). El proxy local sirve el dashboard en http://localhost:8000 y agrega los headers CORS correctos, además de inyectar la API key desde el entorno. Es la solución más simple sin pasar a Fase 2 (backend Flask).
